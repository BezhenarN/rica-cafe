# Production-ready сайт кафе с доставкой (MVP)

## Решения зафиксированы
- **Объём (1-я итерация):** каталог+фильтры, конструктор пиццы, корзина, чекаут, ЛК, админка заказов, трекинг статуса, PWA, SEO, анимации. Бонусы/рекомендации/Telegram-WhatsApp/платежи — **вне скоупа**.
- **Окружение:** только код + README. Система не модифицируется (нет Node/Docker на машине — это нормально, проверка запуска позже пользователем).
- **Структура:** `/frontend` (Next.js 15) + `/backend` (NestJS) + `docker-compose.yml` в корне.
- **Дизайн:** оригинальный минимал/foodtech — светлый фон, петрольный акцент, скруглённые карточки, нейтральное имя «Crudo» (легко переименовать).
- **БД:** PostgreSQL + Prisma ORM, поднимается через docker-compose.
- **Изображения:** локальные SVG-плейсхолдеры (компонент `<ProductImage>`).

## BACKEND (NestJS + Prisma + PostgreSQL)

### Конфигурация
- `package.json`, `tsconfig.json`, `nest-cli.json`
- `.env.example` (DATABASE_URL, JWT_SECRET, PORT, CORS_ORIGIN)
- `prisma/schema.prisma` — полная схема БД
- `prisma/seed.ts` — тестовые категории/товары/опции пиццы/админ
- `src/main.ts` — bootstrap + CORS + глобальный ValidationPipe + Swagger

### Модули NestJS
1. **`auth`** — JWT-стратегия, `POST /auth/register`, `POST /auth/login`, `GET /auth/me`, bcrypt. Roles guard (`@Roles('ADMIN')`).
2. **`users`** — профиль, `PATCH /users/me`, адреса доставки CRUD.
3. **`products`** — категории и товары; `GET /products` (фильтры: categoryId, isVegan, isSpicy, q, sort), `GET /products/:slug`. Каждый товар имеет варианты размера/цены.
4. **`pizza-builder`** — `GET /pizza/options` (размеры, типы теста, соусы, ингредиенты с ценами).
5. **`orders`** — `POST /orders` (с серверным пересчётом цен из БД против подделки), `GET /orders/:id` (с анализом принадлежности), `GET /orders` (свои), `GET /orders/:id/status` (для polling-трекинга).
6. **`admin`** — защищённые роуты: товары CRUD, заказы список + `PATCH /admin/orders/:id/status` (запускает апдейт статуса → трекинг).

### Сущности Prisma
`User`(role: CUSTOMER|ADMIN), `Address`, `Category`, `Product`(+ProductVariant для размеров), `PizzaSize`, `DoughType`, `Sauce`, `Ingredient`, `Order`(status enum: CREATED→CONFIRMED→COOKING→ON_THE_WAY→DELIVERED|CANCELED), `OrderItem`, `OrderItemConfig`.

### Трекинг статуса
Polling на клиенте (`GET /orders/:id/status`, каждые 5 сек) + опционально WebSocket-гейтвей (`orders.gateway.ts`) для живого пуша. В админке — кнопки смены статуса.

## FRONTEND (Next.js 15 + TS + Tailwind + Framer Motion + Zustand + React Query + PWA)

### Конфигурация
- `package.json` (Next 15, React 19, Tailwind, Framer Motion, Zustand, @tanstack/react-query, ky, next-pwa, zod)
- `next.config.mjs` (PWA через next-pwa, proxy `/api` → backend), `tsconfig.json`, `tailwind.config.ts`, `postcss.config.mjs`
- `public/manifest.json`, `public/sw.js`-генерация (next-pwa), иконки-плейсхолдеры
- `.env.local.example` (NEXT_PUBLIC_API_URL)

### Дизайн-система (`app/` + `components/ui/`)
- Tailwind-токены: фон `#FAFAF7`, текст `#1A1D1F`, акцент петроль `#0D5C57`, mint-accent `#7CE7C3`, граница `#ECECE6`.
- Базовые UI-примитивы: `Button`, `Input`, `Badge`, `Card`, `Sheet`(bottom-sheet mobile), `Modal`, `Tabs`, `Skeleton`, `QuantityStepper`, `Chip`(фильтр), `Toaster`.
- Шрифт: Inter (через `next/font`).

### Состояние и данные
- `lib/api.ts` — типизированный клиент (ky) с базовым URL `/api`.
- `lib/query-client.ts`, `app/providers.tsx` (React Query провайдер).
- `store/cart-store.ts` (Zustand, persist в localStorage) — позиции, кастомные пиццы, пересчёт totals.
- `store/ui-store.ts` — открыта ли корзина/меню.
- `hooks/` — `useCart`, `useProduct`, `useOrders`, `useAuth`.

### Страницы (App Router, SSR где имеет смысл)
| Маршрут | Назначение | Рендеринг |
|---|---|---|
| `/` | Hero, баннеры, категории, топ-товары | SSR (ISR) |
| `/menu` | Каталог + фильтры/сортировка/поиск | SSR + клиентские фильтры через RQ |
| `/menu/[slug]` | Карточка товара + варианты + «добавить» | SSG |
| `/pizza-builder` | Конструктор пиццы (живой пересчёт цены) | CSR |
| `/cart` | Состав корзины, очистка, переход к чекауту | CSR (persist) |
| `/checkout` | Контакты, адрес, оплата(наличные/карта при получении), подтверждение | CSR |
| `/orders/[id]` | Трекинг статуса (timeline + polling) | SSR + polling |
| `/account` | ЛК: вход/регистрация, профиль, история заказов, адреса | CSR (auth) |
| `/admin` | Админка: таблица заказов + смена статуса, CRUD товаров | CSR (auth ADMIN) |

### Компоненты фич
- `<Header>` (sticky, мини-корзина, навигация, бургер на мобиле), `<Footer>`, `<MobileNav>` (нижняя навигация как у натив-приложений — фишка foodtech).
- `<ProductCard>`, `<ProductGrid>`, `<FiltersPanel>` / `<FiltersSheet>` (моб.), `<SortSelect>`.
- `<PizzaBuilder>` — размеры, тесто, соус, ингредиенты-чипсы, live-превью цены, кнопка «в корзину».
- `<CartDrawer>` (выезжающая панель справа / снизу на мобиле), `<CartItem>`, `<CartSummary>`.
- `<OrderTracker>` — таймлайн статусов с анимацией, автообновление.
- `<AuthForms>` — login/register с валидацией (zod + react-hook-form).
- `<ProductImage>` — рендер SVG-плейсхолдера по slug/типу блюда (цвет + подпись названия).

### Анимации (Framer Motion)
- Появление карточек в каталоге (stagger), hover-эффекты, анимация добавления в корзину, переходы страниц, анимация таймлайна трекинга, slide-in корзины.

### SEO
- `app/layout.tsx` — метаданные, Open Graph, manifest.
- JSON-LD (`Restaurant`, `Menu`, `BreadcrumbList`) — компонент `<JsonLd>`.
- `app/sitemap.ts`, `app/robots.ts`.
- Семантический HTML, lazy-load изображений, alt.

### Производительность (цель Lighthouse 95+)
- next/image, code-splitting, ISR для каталога, persist-корзина без запросов, минимальный JS, server components для тяжёлых списков.

### PWA
- `next-pwa`, `manifest.json` (name, icons, theme_color, display: standalone), иконки-плейсхолдеры 192/512. Установка на телефон.

## Что НЕ входит в эту итерацию (честно)
- Бонусная программа, рекомендации по покупкам, интеграция Telegram/WhatsApp, реальный платёжный шлюз, отзывы/рейтинги, мульти-заведение/филиалы, i18n, тесты (e2e/unit) — в roadmap.

## Риски / ограничения
- **Без запуска:** на машине нет Node/Docker, поэтому код **не будет скомпилирован/проверён** — он аккуратно пишется по актуальным API, но первый запуск может потребовать мелких правок версий. README покрывает установку.
- **Объём:** даже MVP — это ~50+ файлов и несколько тысяч строк. Буду реализовывать методично по модулям.

## Порядок реализации
1. Корень: `.gitignore`, `docker-compose.yml`, `README.md` (каркас).
2. Backend: конфиг → Prisma schema+seed → все модули → Swagger.
3. Frontend: конфиг/Tailwind/PWA → дизайн-система → API/Stores → страницы и компоненты по приоритету (главная → каталог → конструктор → корзина → чекаут → ЛК → админка → трекинг).
4. Финальный README с инструкцией запуска.
