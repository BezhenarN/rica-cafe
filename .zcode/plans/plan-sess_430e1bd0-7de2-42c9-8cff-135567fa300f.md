## Миграция NestJS → Vercel API Routes (Next.js App Router)

### Цели
- Убрать NestJS backend полностью. Вся логика — в Next.js API Routes.
- Один деплой на Vercel: фронтенд + API + Prisma.
- Image uploads → Cloudflare R2 (S3-compatible).
- WebSocket → остаёмся на 5s polling (уже работает).

### Этап 1: Пакеджинг и конфиг
- Добавить в `frontend/package.json`: `@prisma/client`, `prisma`, `bcryptjs`, `@types/bcryptjs`, `@types/bcrypt`, `jsonwebtoken`, `passport`, `passport-jwt`, `@types/passport-jwt`, `class-transformer`, `class-validator`, `multer`/`multer-s3`, `@aws-sdk/client-s3`, `@aws-sdk/s3-request-presigner`, `@cloudflare/workers-types`.
- Копируем `backend/prisma/schema.prisma` в корень frontend.
- Создаём `frontend/prisma/seed.ts` из бэкенда.
- Создаём `frontend/vercel.json` с ретраями и runtime `edge`/`nodejs` для routes.

### Этап 2: API Routes (копируем логику из NestJS)

| API Route | Методы | Описание |

### Этап 3: Shared middleware и guards

Создаём reusable helpers:
- `frontend/src/lib/auth.ts` — `verifyToken()` для API routes (JWT verification).
- `frontend/src/lib/rate-limit.ts` — простой rate limiting через памяти (или Vercel middleware).
- `frontend/src/lib/roles.ts` — `isAdmin()` guard.
- `frontend/src/lib/validate.ts` — validation wrapper для class-validator.
- `frontend/src/lib/prisma.ts` — singleton PrismaClient (для serverless cold starts).

### Этап 4: Cloudflare R2 для image uploads
- Создаём R2 bucket в Cloudflare Dashboard.
- Настройка `@aws-sdk/client-s3` с `endpoints: { r2: cf_account_id }.r2.cloudflare.com`.
- `/api/admin/products/[id]/image` — multipart parsing → upload to R2 → обновить `imagePath` в БД.
- Обновляем admin page: используем `api-client.ts` (или `getToken()`) вместо `localStorage.getItem('token')`.

### Этап 5: Фиксы frontend

- **home-page-client.tsx**: убрать hardcoded `http://localhost:3001`, использовать `fetch('/api/categories')` (через Next.js rewrites к API routes).
- **admin/page.tsx**: исправить `localStorage.getItem('token')` → `import { getToken } from '@/lib/api-client'`.
- **api-client.ts**: обновить base URL для API routes (когда API routes локальные, это `/api`).

### Этап 6: Удаление NestJS backend
- Удаляем/коммитим `backend/` (оставляем как backup).
- Обновляем `.gitignore`.
- Обновляем `render.yaml` — удаляем backend service.
- Обновляем `docker-compose.yml` — удаляем postgres (или оставляем только для dev).

### Этап 7: Environment vars для Vercel
- `DATABASE_URL` — Vercel Postgres (или Neon, Supabase).
- `JWT_SECRET` — Vercel secrets.
- `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`.
- `ADMIN_EMAIL`, `ADMIN_PASSWORD` — для seed.
